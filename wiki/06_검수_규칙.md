# 06. 검수 규칙 — 오탈자·통일성 체크 방법론

## 🔍 오탈자 자동 검사 (Python · openpyxl)

### 1) 셀 내부 단어 중복 (XX XX 패턴)
```python
import re
for m in re.finditer(r'([가-힣]{2,4})\1', cell.value):
    pattern = m.group(1)
```

**False positive (제외해야 할 자연 패턴)**:
- 가가, 를를, 이가, 에에, 의의, 도도, 서서, 하하, 간간, 단단, 연연

### 2) 셀 경계 중복 (줄바꿈 시 마지막 글자가 다음 셀 첫 글자에 또 들어감)
```python
# 셀1 마지막 글자 == 셀2 첫 글자 검사
if v1.rstrip()[-1] == v2.lstrip()[0]:
    if '가' <= v1.rstrip()[-1] <= '힣':
        # 의심 케이스 (단, 가/를/이/에/의/도/서/하 로 끝나면 자연스러운 경우 많음)
```

**과거 발견된 케이스 (모두 수정됨)**:
- "귀귀책" (셀1 끝 "귀" + 셀2 시작 "귀책")
- "에에" (결제일에 + 에 수납대행사)
- "자기기를" ("자기 + 기를")
- "협조조" (협조 + 조하여야)
- "공과과금" (제세공과 + 과금)
- **"침침" (B2B v5 제18조)** — "회사 소유권 침" + "침해 행위" → 셀1 끝 "침" 제거하여 "소유권 침해"로 자연 연결

### 3) 띄어쓰기 오류 검사 패턴
- 통보하여야한다 → 통보하여야 한다
- 납부해야하 → 납부해야 하
- 하여야한다 → 하여야 한다
- 만료일이후 → 만료일 이후
- 음주운전등 → 음주운전 등 / 운전등 → 운전 등
- 할부판매기간 → 할부판매 기간
- 사전동의 → 사전 동의
- **통보한후 → 통보한 후** (B2B v6에서 발견)
- **미완납시 → 미완납 시 / 완납시 → 완납 시** (B2B v6에서 발견)
- **N일이내 → N일 이내** (정규식 `(\d+)일이내`로 검사)

### 4) 미세 오탈자 (B2B v6에서 발견된 추가 패턴)
- "상환하여 한다" → "상환하여야 한다" ("야" 누락)
- "계약자는 는 / 회사는 는" (조사 "는" 중복)
- "처분 가능한다" → "처분할 수 있다" (어색한 표현 — "가능"을 "한다"로 억지로 종결)
- "사용이익을회사" → "사용이익을 회사" (조사+명사 붙음)
- 이중 공백 "  " (단, 라벨용 디자인 의도된 것은 제외 — 별지 헤더 "제1조  구상금" 등, 계약서 입력란 등)

## 🔄 통일성 검사 — 같은 의미 조항 본문 대조

### 매크로용 셀 좌표 (계약서 1면 — B2C 기준)
```
C6/F6/I6   = 차종/차량번호/색상
C7/F7/I7   = 차대번호/정비여부/보험연령
C11/F11/I11 = 성명/주민번호/연락처
C12        = 주소
C17/F17/I17 = 계약유형/상품유형/기간
C18/F18/I18 = 사용료/보증금/결제일
C19/F19    = 납입방법/청구시작일
C20        = 납입계좌
C23/F23/I23 = 회사상호/사업자번호/대표이사
```

## 🎯 통일이 필요한 vs 의도된 차이

### 의도된 차이 (그대로 OK)
- **회사명** (포어스 vs 한국모터사이클리스)
- **상품명** (종합렌트/책임렌트/할부판매)
- **워딩** (렌트료/할부금)
- **보험 가입 주체** (회사 vs 계약자)
- **금지행위 (2)호** (할부판매는 본인 명의 보험 표현)
- **위약금 산식** (총 렌트료 × 20% / 총 할부금 × 20%)
- **B2B의 사용자(라이더) 관련 표현** (계약자가 사용자에게 운행하게 한 경우 등) — B2C엔 없음
- **현금영수증(B2C) vs 세금계산서(B2B)** — 계약자 성격이 다름

### 통일해야 할 표현 (자주 놓침)
- "수리를 진행하며" vs "수리를 받으며" → **"받으며"로 통일** (단 B2B는 "사용자가 ~ 수리를 진행하게 하며" — 사용자 개념 때문에 의도된 차이)
- "렌트료의 미납" vs "렌트료 미납" → 둘 중 하나
- "지급한다" vs "지급하여야 한다" → 통일
- "사전동의" vs "사전 동의" → **띄어쓰기 통일**
- **"아니된다" vs "아니 된다" → "아니 된다"로 통일** (B2C 기준)
- **"하지 아니한다" vs "하지 않는다" → "하지 않는다"로 통일** (B2B v6 사용자 결정)
- **"통보한다" vs "통지한다" → "통지"로 통일** (B2B v6에서 "사전 통보"를 "사전 통지"로)

## 🔢 조항 번호·흐름 검사 (B2B v5~v6에서 자주 사고)

조항 통합·삭제 작업 후 **반드시** 검사:
- 조항 헤더 정규식 `^제\s*(\d+)\s*조\s*\(([^)]+)\)\s*$` 로 전체 추출 → 번호 연속성 확인
- 헤더 누락 확인 (본문 ①②③만 있고 "제○조 (제목)" 없는 경우)
- **본문 내 조항 참조** (`제N조` 표현) 가 실제 존재하는 조항을 가리키는지 — 통합/재번호 후 깨지기 쉬움
- ⚠ **openpyxl로 한 컬럼만 재구성해도 인접 컬럼 셀이 손실될 수 있음** (B2B v6 통합 시 D 컬럼만 작업했는데 B 컬럼 제20조 손실). 작업 후 B·D 양쪽 조항 흐름 전수 확인 필수.

## 🧪 PDF 인쇄 검증 (LibreOffice 활용)

```bash
libreoffice --headless --convert-to pdf 파일.xlsx
pdfinfo 파일.pdf  # 페이지 수 확인
pdftoppm -r 100 파일.pdf page -png  # 페이지별 이미지
```

⚠ **LibreOffice 한계**: `scale`·`fitToPage`·`fitToHeight` 설정을 정확히 반영하지 못함. LibreOffice 변환에서 3페이지로 나와도 **실제 Excel에서는 fitToHeight 설정대로 2페이지에 맞춰질 수 있음** → 최종 페이지 수는 사용자가 Excel 인쇄 미리보기로 확인해야 정확.

**A4 페이지 배분**:
- 계약서 1면: 1페이지 (scale 자동 적용)
- 별지 구상금: 1페이지
- 이용약관: 2페이지 목표 (B2B는 조항 많아 압축 필요 — `08_B2B_약관.md` 참조)
- 계약리스트: 인쇄 X 권장 (컬럼 많음)
